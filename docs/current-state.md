## Search

Используется:

* `/api/search`
* страница `/search`

Поиск выполняется через:

* debounced-запросы;
* отмену устаревших запросов;
* единый API endpoint.

Мобильная и десктопная версии используют общее состояние поиска.

История поиска хранится на клиенте в `localStorage`.

## Product Listing

Общий Product Listing используется для:

* Category;
* Collection;
* Search.

Логика листинга разделена между app-слоем каталога и product service.

Поток данных:

```text
URL
    │
    ├── parsing и normalization
    ├── pagination
    ▼
Product Listing use case
    │
    ├── получение товаров
    │
    └── получение пользовательского состояния
    │
    ▼
Product Listing DTO
    │
    ▼
UI
```

Для авторизованного пользователя Product Listing дополнительно формирует состояние избранного для товаров.

Поддерживаются параметры:

* query
* sale
* inStock
* discount
* priceFrom
* priceTo
* sort
* page
* view=append

URL преобразуется в нормализованную модель фильтров и сортировки.

Пагинация обрабатывается независимо от фильтров и сортировки.

Product Service получает уже нормализованные данные и не зависит от URL.

Фильтры каталога используют серверные метаданные:

* minPrice
* maxPrice
* maxDiscount
* totalProductsCount

## Product Listing UI

Каталог использует единый layout для Product Listing, включающий фильтрацию, сортировку, отображение товаров и управление пагинацией.

Отображение списка товаров отделено от управления фильтрами, сортировкой и пагинацией.

## Favorites

Избранное поддерживает два режима:

* guest favorites;
* authenticated favorites.

Guest favorites хранятся в `localStorage`.

Избранное авторизованного пользователя хранится в PostgreSQL.

Состояние избранного доступно через общий client-side state, который используется Header и компонентами товаров.

Для guest источником данных является локальное состояние, для авторизованного пользователя — серверное состояние.

После авторизации локальные favorites объединяются с серверными. После успешной синхронизации локальное состояние очищается.

При ошибке синхронизации локальные favorites сохраняются.

Изменение состояния избранного выполняется оптимистически. При ошибке состояние откатывается.

Product Listing включает пользовательское состояние избранного для авторизованного пользователя.

Страница Favorites использует отдельные сценарии получения товаров для authenticated и guest пользователей. Оба сценария используют общий механизм получения товаров.

## Product Domain

Работа с товарами организована через доменный сервис, DTO и общий Product Listing.

Страница товара использует отдельные page-specific компоненты для отображения информации о товаре и слайдера изображений.

Для прикладных сценариев используются отдельные use cases, когда требуется композиция нескольких доменных операций.

Header поддерживает desktop и mobile navigation.

Navigation интегрирована с состоянием авторизации и предоставляет доступ к основным разделам магазина.

Header отображает состояние избранного, включая количество сохранённых товаров.

## Authentication

В проекте интегрирован Better Auth.

Текущий authentication flow основан на email.

Реализованы:

* sign in по email и паролю;
* sign up по email и паролю;
* email verification через OTP;
* password reset;
* установка нового пароля;
* смена email;
* подтверждение нового email;
* sign out.

Email отправляется через отдельный email service.

Для защиты auth-операций используется rate limiting.
